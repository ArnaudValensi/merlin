# Notes System

Reference documentation for Merlin's 3-layer notes architecture: user profile, daily logs, and knowledge base. This file is the complete spec; the notes skill (`skills/notes/SKILL.md`) is the thin operating card agents load per session, and `merlin kb check` is the executable subset of these rules.

## Overview

Merlin's notes live in the notes directory (resolve with `merlin config notes-dir`, default `~/.merlin/notes/`):

```
notes/
├── user.md                      # Layer 1: User profile (facts, preferences)
├── logs/                        # Layer 2: Daily logs
│   └── YYYY-MM-DD.md
├── kb/                          # Layer 3: Knowledge base (typed OKF-style notes)
│   ├── index.md                 # GENERATED by `merlin kb index` (reserved)
│   ├── log.md                   # Gardener change journal (reserved, optional)
│   ├── conventions.md           # Living format rules + type vocabulary (a normal note)
│   └── <slug>.md                # One concept per file
├── media/                       # Binary assets, each owned by one note via resource:
└── *-history.md / *.json        # Job-owned history files (not notes)
```

The notes dir is a git repo; `notes/sync.py` auto-commits and pushes (debounced) when `NOTES_GIT_SYNC` is enabled.

## Design

The KB follows Google's Open Knowledge Format (OKF v0.1, a directory of markdown + YAML frontmatter, one required field) for its on-disk shape, and Karpathy's LLM-wiki model for its operation: agents write and tend the notes, humans curate and ask. Two principles govern the implementation:

1. **Machine narrows and validates, agent judges and writes.** No code ever writes a link or picks a "related" note. The generated index gives the agent total knowledge of the catalog; semantic matching is the agent's reading, not a scorer. Deterministic work (index generation, conformance) is code.
2. **The code is the enforcement.** Anything mechanically checkable lives in `kb add` validation and `kb check`, not in prose that can drift.

Epic history: `epics/cli/kb-okf-redesign/` in the merlin-saas repo.

## Layer 3: Knowledge Base

### Note format

```yaml
---
type: technique
title: Reggae Organ Bubble
description: Hammond drawbar settings and hand roles for the bubble
tags: [reggae, organ]
resource: https://example.com/course        # optional; list allowed
created: 2026-07-21
updated: 2026-07-21
---

# Reggae Organ Bubble

Body. Links are prose: Extends [Piano Progressions](reggae-piano-progressions-classiques.md)
with the organ-side voicings.
```

| Field | Required | Semantics |
|-------|----------|-----------|
| `type` | yes | What kind of note this is, one value. Free string; the living vocabulary is in `kb/conventions.md` (technique, tool, company, analysis, project, transcript, decision, reference, index). `kb add` prints a notice with existing types when a new one appears. |
| `title` | recommended | Display name |
| `description` | recommended | One line, specific; feeds the index and search results (index truncates at 180 chars) |
| `tags` | recommended | Topics, plural, lowercase kebab-case |
| `resource` | optional | URI of the source asset: external URL or `media/<file>` path. A YAML list may claim several media files |
| `created` / `updated` | recommended | ISO dates; `updated` = last meaningful change (OKF calls this `timestamp`) |

Extra keys are allowed (OKF rule); consumers preserve what they do not know. Frontmatter is parsed as real YAML (`lib/frontmatter.py` in-process; the PEP 723 command scripts carry private copies). Dates are normalized to ISO strings. Values with colons or other YAML-hostile characters are quoted by the writer (`yaml_value()`).

### Links

Links live in the body as normal markdown links, each carried by prose stating the relationship, inline or as an annotated bullet. A bare link (no prose beyond the link on its logical line) is a `kb check` finding. There is no `related:` frontmatter and no auto-linking; the retired lexical scorer's history is in the epic doc.

Link extraction (shared by `kb add` validation and `kb check`) ignores: external URLs, non-`.md` targets, links inside fenced code blocks or inline code spans, and targets with directory components (the KB is flat; those point outside the bundle). Wrapped bullet annotations and nested annotation sub-bullets are joined into logical lines so their prose counts.

### Reserved files (in `kb/`)

- `index.md`: generated by `merlin kb index`. Frontmatter carries only `okf_version`. Grouped by type, entries `* [Title](file.md) - description`. Never hand-edited; `kb add` refreshes it after each create, `kb check` flags it when stale.
- `log.md`: change journal (newest first, `## YYYY-MM-DD` headings), written by the KB gardening job.
- `_index.md`: legacy hand-maintained index; its presence is a `kb check` finding.

Reserved files are excluded from note listings, search results, tag/type vocabularies, and duplicate detection.

### Media

Every file in `<notes-dir>/media/` must be claimed by exactly one note's `resource:`. The owning note's body is the asset's searchable textual projection: description for images, transcript for audio/video, extraction for PDFs. Orphaned media is a `kb check` finding. Note the git-size caveat: media is synced with the notes repo, so large assets deserve thought before landing there.

### Commands

| Command | Role |
|---------|------|
| `merlin kb add` | Create a note. Requires `--type`; validates duplicates (exact slug/title) and link targets; prints notices for novel types/tags with the existing vocabulary; refreshes `index.md`. Never writes links. `--dry-run` previews. |
| `merlin kb index` | Regenerate `kb/index.md`. Deterministic, safe anytime. |
| `merlin kb check` | Conformance gate, exit 1 on findings: parseable frontmatter, non-empty `type`, no legacy fields (`related`, `summary`), resolvable and described body links, index freshness, media ownership. |
| `merlin notes search kb` | List all (title, type, description, tags), or filter with `--keyword`, `--tag`, `--type`. |
| `merlin notes search tags` | Tag vocabulary with counts and files. |

### Index injection

`lib/agent_context.py` exposes a `kb_index` layer: `kb/index.md` with its frontmatter stripped, included in both the `managed-assistant` and `headless-worker` recipes. Every agent session starts knowing the full KB catalog; retrieval is reading comprehension over the index followed by targeted `cat`s, not blind keyword search. At 75 notes the index costs ~4k tokens per session. If the corpus grows past the point where this is comfortable (several hundred notes), the planned evolution is narrowing layers (type/tag filters first, embeddings as an advisory shortlist last); the epic doc records that design.

### Maintenance loop

A daily `kb-gardening` job (user-space, managed via `merlin job`) is the lint pass: it runs `kb check` and fixes findings, audits weak descriptions, consolidates near-duplicate tags/types, deletes junk, refines 1-2 old notes through the CEQRC lens, and appends its actions to `kb/log.md`. It does not add links for structural reasons (shared tags, orphan status): links require a stated relationship.

## Layer 1: User Profile (`user.md`)

Flat markdown, durable facts about the user, auto-injected into agent context (`user_memory` layer). Managed with `merlin remember add|list` (sections: identity, preferences, context, notes). Note: `remember add` appends; it does not deduplicate.

## Layer 2: Daily Logs (`logs/YYYY-MM-DD.md`)

One file per day; entries are `## HH:MM — <title>` blocks. Written directly by agents (no dedicated command); searched with `merlin notes search log [--keyword] [--from/--to/--last]`.

## History files

`app-ideas-history.md`, `self-reflection-history.md`, `digest-history.json`, and similar are job-owned working files that happen to live in the notes dir. They are not notes and are excluded from the notes editor listing (`EXCLUDE_FILES` in `notes/routes.py`).
